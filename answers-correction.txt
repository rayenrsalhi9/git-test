Q:  Create a new repo on GitHub?
A:  Click the "+" icon in the top-right corner → "New repository" → fill in the details → click "Create repository"

Q:  Copy a repo onto local from GitHub?
A:  git clone git@github.com:user-name/repo-name.git

Q:  Default name of your remote connection?
A:  origin

Q:  What `origin` is in `git push origin main`
A:  It is the alias (default name) for the remote repository URL on GitHub, so we don't have to type the full URL every time

Q:  What `main` is in `git push origin main`
A:  It is the name of the local branch being pushed, AND the name of the target branch on the remote (GitHub) to push into — both happen to share the same name "main"

Q:  Explain the two-stage system that Git uses to save files.
A:  Stage 1 — Staging: use `git add` to move changes into the staging area (a preparation zone where you choose exactly what will go into the next commit)
    Stage 2 — Committing: use `git commit` to permanently save everything in the staging area as a snapshot in Git's local database

Q:  How do you check the status of your current repository?
A:  git status

Q:  How do you add files to the staging area in Git?
A:  git add <file>   ← stages a specific file
    git add .        ← stages ALL changed files in the current directory

Q:  How do you commit the files in the staging area and add a descriptive message?
A:  git commit -m "your message here"

Q:  How do you push your changes to your repository on GitHub?
A:  git push              ← shorthand version
    git push origin main  ← explicit version (push local "main" branch to remote "origin")

Q:  How do you look at the history of your previous commits?
A:  git log   (press "q" to exit)
